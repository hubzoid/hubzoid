# Hubzoid 1.3.2

This maintenance release adds optional Claude credential failover, fixes native
Windows startup and cleanup, and confirms permanent support for both chat interfaces.

## Keep answering when a Claude credential reaches its limit

Configure one primary Claude OAuth credential and up to two backups. Hubzoid
uses them in order, keeps the same model and permissions, and switches only on
confirmed usage-limit or authentication failures. Shared cooldowns avoid repeated
attempts against an unavailable credential. A limited credential becomes eligible
for one recovery probe after its reset time, or after five minutes when no reset
is available.

If no content or tool activity has started, the backup can answer the same request.
Once work begins, Hubzoid ends the failed turn and uses a backup for a later request;
it does not replay completed actions. No admin configuration screen or alerts are
added. A single credential keeps its existing behavior.

See [configuration and limits](../DEPLOYING.md#claude-credential-failover).
Multiple credentials may share the same quota; backups do not guarantee availability.

## Native Windows startup and shutdown

Portable locks replace Unix-only `fcntl` calls in migrations and related state
writers. Windows child-process cleanup no longer relies on `SIGKILL` or `killpg`.
The same fixes cover workflow ownership, schedules, eval reports, inbound deduplication,
Codex credential refresh and GitZoid checkouts.

The [quickstart](../quickstart.md) includes PowerShell commands. Native Windows
acceptance covers the headless bridge, SQLite locks and shutdown; it is not a
claim that every runtime and interface combination has been validated on Windows.

## Both chat interfaces remain supported

Native chat remains the default. Open WebUI remains an optional install with
permanent, equal support and release-testing requirements. No interface is removed,
and no new `assistantui` package extra is introduced.

## Upgrade

Back up Hub and operational data, install `hubzoid==1.3.2` (or
`hubzoid[openwebui]==1.3.2` for Open WebUI), then restart all Hubzoid processes.
Existing Hub folders need no new required files or fields. Failover is opt-in.
See [upgrading](../UPGRADING.md).

## Validation limits

Live subscription exhaustion and provider reset recovery have not been induced.
Structured SDK regression tests verify the switching policy, cancellation, accounting,
secret masking and no replay after work starts. They do not establish real-provider
quota behavior or a provider-approved shared subscription deployment.
