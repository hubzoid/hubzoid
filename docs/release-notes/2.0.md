# Hubzoid 2.0 (unreleased)

Hubzoid 2.0 has one chat interface, its own web app, with Settings in the same
app. Open WebUI is removed. Sign-in is Hubzoid's own, with two-step sign-in,
personal API keys and company sign-in. Agents can ask a person before they act,
and people can change the agent's instructions from chat, with review.

This page is a draft for the release. Until 2.0 is tagged, `main` reports
`2.0.0.dev0`.

## Before you upgrade

- **Open WebUI is gone.** A deployment that still needs it stays on 1.x
  (`pip install "hubzoid<2"`). To move, follow
  [Upgrading to 2.0](../UPGRADING.md#upgrading-to-20-open-webui-removed): back
  up, check readiness, rehearse on a copy (a single hub or a whole gateway),
  then `hubzoid migrate openwebui --apply`.
- **Some old settings stop the start** until renamed (`WEBUI_AUTH`,
  `WEBUI_URL`, `WEBUI_ADMIN_*`, `HUBZOID_GATEWAY_ADMIN_*`, `HUBZOID_UI`). The
  start names each one and what to use instead.
- **Access comes from grants only.** Groups and `BYPASS_MODEL_ACCESS_CONTROL`
  give none. The migration's dry run counts the people who would have no agent
  access.
- **Administrators set up two-step sign-in** at their first sign-in.
- **Old API keys stop working.** People make personal keys in Settings → Security.

## Chat

- A new chat built on assistant-ui: streaming answers, tool activity, reasoning,
  edit and regenerate as branches you can switch between, Stop, and a queue
  for the next message (send after this reply, or interrupt).
- Folders, pins, archive, search across titles and messages (only what you can
  read), export and import (Hubzoid, Open WebUI and LibreChat files).
- Files and documents: attachments keep their identity, documents the agent
  writes are versioned, and previews run in a sandbox with no network.
- Sources: collections of your files, notes and web pages that answers cite,
  passage by passage.
- Sharing: preview exactly what a snapshot link shows, then publish it for named
  people or everyone signed in (public links only if an administrator allows
  them). Turning a link off stops it at once. Collaborators read a chat or
  write on their own branches, always with their own access.
- Models people may pick, presets, and compare (extra answers as branches).
- Dictation and read aloud in the browser, where an administrator allows it.

## Settings

- One Settings page for everyone: profile, security, memory, notifications and
  data for each person; agents, people and access, activity, schedules,
  workspace settings, brand, health and advanced settings for administrators.
  Old `/portal/` links open the same section.
- Agent instructions: edit `AGENTS.md`, skills and shared prompts as drafts,
  review them, then publish. Each publication is one Git commit.
- Brand: draft, review and activate the deployment's name, logo and colours.
- An agent's display name comes from `display_name:` in its `AGENTS.md`.

## Sign-in and access

- Two-step sign-in (authenticator app) with recovery codes, required for
  administrators by default. A device list, sign out one device or everywhere,
  and "Confirm it's you" before sensitive changes.
- Personal API keys (`hzp_…`) with a scope (chat, read or everything you can
  do), optional agent limits and expiry. The `hubzoid auth` and `hubzoid api`
  commands use the same API as the web app.
- One access check on every tool call, for every runtime. Blocking, deleting or
  signing out a person stops their running work at its next tool call.
- Every run records who it is for before any model or tool runs.
- Company sign-in with SAML 2.0 (`hubzoid[saml]`) and SCIM 2.0 accounts.

## People in the loop

- Approvals and questions (`hitl.yaml`, optional): a tool or connector can ask
  always, once, or (for MCP) on writes. Only the person who asked, or named
  approvers, decide. "Waiting for you" lists everything; Slack, WhatsApp and
  email can carry the request.
- Workflows can wait for a person (`hub.ask`, `hub.approve`) and for a plan's
  approval (`hub.review_plan`).
- Workflow access: who may run, schedule, change or see each workflow.
- Repeated requests: "do this every Monday at 9" becomes a schedule after a
  yes; each run answers in a new private chat.
- Hub changes: the agent proposes exact edits to `AGENTS.md`, `knowledge/` and
  `skills/`; a person reviews and applies them as one Git commit.
- Personal memory: one note per person per agent, saved only when the person
  asks, editable in Settings → Memory.

## Not in 2.0 yet

- Some Open WebUI features have no counterpart yet (the parity gap report
  lists them). Notes, channels and calendars are not carried.
- The migration imports people, chats, attachments and share links. Pins,
  folders, tags, ratings, prompts, skills, knowledge bases, memories, tools
  and functions are not imported; readiness says what to do with each.
- Verified mainly on the Claude runtime and SQLite. PostgreSQL, the Codex and
  OpenAI Agents runtimes, and live Slack, WhatsApp, Okta and Entra have unit
  tests only.
